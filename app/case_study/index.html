GivemeaChance

A job-search assistant that says which postings are worth your time and why, then writes a résumé and cover letter that only use what is true about you.

Live demoSource code

The problem

Applying well means reading every posting, comparing it with your background and writing a résumé that fits it. Most tools do one of two things: send one résumé everywhere, or let a language model write whatever sounds good, including experience you do not have.

I wanted a tool where the score can be explained, the documents can be checked, and I can show how well both work with numbers instead of claims.

Approach

The user reviews and approves a Master Profile built from their résumé. Every later step reads only that profile. For each posting the model rates five dimensions with evidence, and code computes the total, so the same ratings always give the same score. Postings are read in full, because a preview hides the years and skills that decide the fit.

Résumés and letters are written only for jobs the user chooses. Afterwards a second pass checks every claim against the profile and marks it supported, inferred or unsupported, and the user sees the unsupported ones before exporting.

How it was measured

I collected 48 real postings and labelled 47 of them by hand for an early-career data-science résumé, before looking at any score. Each got an apply, maybe or skip label and a level: fits, too senior, too junior or unsure.

The level measure is the share of pairs, one role that fits and one that asks for more, where the seniority rating puts the fitting role higher. 0.50 is a coin flip. One command, python scripts/labelling.py report, reproduces the matching figures on this page, given the labelled data, which stays private. The fact-check figures come from scripts/factcheck_eval.py.

What the measurements changed

1 → 7

Fitting roles in the deck. A cap tied the score to "3+ years" or a missing skill and hid good matches. Now only a hard gate, such as a required licence, caps a score.

0.68 → 0.83

Level agreement after scoring the full posting instead of a preview, with the prompt and profile fixes made along the way (the first run used the preview and an older model). Postings that state the years asked went from 1 of 48 to 39 of 48.

The years a posting asks for are now shown next to the score, read from the text by plain code with no model call. The score is unchanged, because the person applying decides whether to apply above their level.

Does the fact check work?

I planted wrong claims in generated documents for a fictional profile and counted how many the audit caught. The blunt set had 20 documents with 31 planted claims: invented employers, numbers, degrees and certifications. The subtle set had 12 documents with 21 claims, such as an inflated title or a team that was never led.

The cheaper model missed an inflated "Leads a team" and a "Lead engineer" title. I kept it because it is six times faster and the public demo has to answer quickly. The numbers are in the project's decision records for anyone who would choose differently.

Choosing a model

Four models scored the same postings with the same prompt. The intervals overlap, so the choice rests on speed and cost.

The cheapest model puts four jobs I would skip into the deck, so its low price is not a bargain. The larger models were not measurably more accurate here, since the intervals overlap, and are 5 to 8 times slower.

Limits

This is 47 postings, one labeller and one early-career résumé, so the intervals are wide. Only 7 postings are labelled skip, which is why the apply-versus-skip interval runs from 0.56 to 0.92. The score describes fit and does not predict who gets hired. The numbers show the changes helped on this set. They do not show how it will do on every résumé.
